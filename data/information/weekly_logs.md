**Table 3.2: Weekly Logs**

| Week | Responsibilities | Activities Performed | Observations |
|---|---|---|---|
| 1 | Onboarding and orientation | Met the mentor and the team, understood the purpose of the application and my role, and set up the development environment and project access. | Understood how the project is organized and what is expected from my role. |
| 2 | Understanding requirements and design | Studied the application requirements and the provided UI design, reviewed the existing project structure, and planned the screens to be implemented. | Clear understanding of the design at the start reduces rework later. |
| 3 | Reusable components and navigation | Created reusable interface components such as buttons, cards, and input fields, and set up navigation between screens. | Reusable components keep the interface consistent and save development time. |
| 4 | Frontend screen implementation (part 1) | Implemented application screens with layouts, text, and spacing according to the design. | Careful spacing and layout make the interface look consistent on different screen sizes. |
| 5 | Frontend screen implementation (part 2) | Implemented the remaining screens and improved navigation flow between them. | Consistent design across screens improves the user experience. |
| 6 | User Management | Worked on user and profile functionality, including retrieving and updating user information, and connected it with the frontend. | Understood how user data flows between the frontend and the backend. |
| 7 | Workout screens | Implemented the workout-related screens and components for displaying and entering workout data. | Structuring list-based data clearly is important for usability. |
| 8 | Workout Management | Worked on creating, retrieving, updating, and deleting workout data and connected these services to the workout screens. | CRUD operations are the core of most data-driven applications. |
| 9 | Feature Management | Worked on feature flags that enable or disable application features through backend configuration and connected them to the frontend. | Feature flags allow features to be controlled without changing the application code. |
| 10 | Frontend-backend integration | Connected remaining frontend components with backend services, handled the data flow, and added loading and error handling. | Proper handling of loading and error states improves the user experience. |
| 11 | Testing and debugging | Tested the implemented screens and functionalities and fixed the errors and bugs found. | Testing reveals problems that are not visible during development. |
| 12 | Final improvements and delivery | Fixed remaining issues, improved the implemented features based on feedback, and prepared the work for final delivery. | Finalizing a project requires testing, cleanup, and feedback. |Qs
