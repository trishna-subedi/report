\section{Introduction}
An internship is an educational program that integrates classroom study with supervised industry experience \citep{parveen2012}. It enables students to apply theoretical knowledge to real-world projects within a professional organization \citep{nace2022}. Under the B.Sc. CSIT curriculum prescribed by the Institute of Science and Technology (IoST), Tribhuvan University, each final-year student must complete an internship course (CSC461) carrying six credit hours over 10 to 12 weeks with at least 180 working hours \citep{tu2022curriculum}.

In fulfillment of these requirements at Prithvi Narayan Campus, Pokhara, the internship was undertaken at Power Gym Budibazar Pokhara, a fitness center located in Budibazar, Pokhara-26, Kaski, Nepal. The gym operates seven days a week from 5:00 AM to 9:00 PM, providing strength training, personal coaching, and group fitness services. To modernize its operations, the management established a Digitalization Unit. The internship was conducted within this unit under the role of Mobile Application Developer Intern, supervised by company mentor Mr.~Krishna Subedi.

The primary project was the development of Alcedo, a cross-platform mobile fitness application. Alcedo provides gym members with an offline-first digital companion to log workouts, track exercises and sets, consult exercise catalogs, view strength trends, and manage preferences. The intern's responsibilities included user interface implementation, component design, state management, local database persistence, and integration with backend services. This report presents a systematic account of the internship activities and technical work performed.

\section{Problem Statement}
While the B.Sc. CSIT curriculum covers data structures, algorithms, database concepts, and software engineering principles, classroom assignments involve simplified systems that do not expose students to production software challenges such as cross-platform rendering, offline persistence, token-based authentication, and automated testing. Students consequently face a gap between theoretical knowledge and industry practice.

From an organizational perspective, Power Gym Budibazar Pokhara relied on physical front-desk interactions and a Facebook page ($\sim$1.7K followers) for member communication. Neither channel offered functional utility for workout tracking or training management. The absence of a digital platform created the following bottlenecks:
\begin{itemize}
    \item Members relied on memory or paper notebooks to track weights, repetitions, and rest intervals, hindering systematic progressive overload.
    \item Beginners lacked immediate access to verified exercise descriptions and muscle group information when trainers were assisting other clients.
    \item Without data storage or analytics tools, members could not visualize workout frequency, volume trends, or personal records over time.
    \item The gym lacked a branded mobile application to deliver training routines or manage member profiles digitally.
\end{itemize}

Addressing these challenges required developing a dedicated, offline-capable mobile application for gym members, supported by backend services for user profiles, workout data, and dynamic configurations.

\section{Objectives}
The primary objective of the internship was to bridge academic knowledge with professional practice through the development of a cross-platform mobile application and supporting backend modules.

The specific objectives were:
\begin{itemize}
    \item To design and implement responsive user interface components using React Native, Expo, and TypeScript, following centralized design tokens.
    \item To develop structured application navigation using Expo Router across five primary tabs and twenty-four route screens.
    \item To implement client-side state management using Redux Toolkit and offline-first local persistence using SQLite with Drizzle ORM.
    \item To develop backend service modules within NestJS and MongoDB covering User Management, Workout Management, and Feature Management.
    \item To establish secure frontend--backend integration using JWT-based authentication with automatic token refresh.
    \item To ensure software reliability through automated unit tests, component simulations, static typechecking, and systematic debugging.
    \item To develop professional competencies in version control, modular architecture, and documentation practices.
\end{itemize}

\section{Scope and Limitation}

\subsection{Scope}
The internship scope encompassed the design, implementation, and verification of the Alcedo mobile application and its supporting backend services.

The frontend scope included:
\begin{itemize}
    \item A cross-platform mobile client built with React Native 0.86, Expo SDK 57, and TypeScript.
    \item A reusable UI component library with centralized design tokens supporting dark, light, and OLED display themes.
    \item Twenty-four functional screens across five navigation tabs: Workout, Feed, Stats, History, and Settings.
    \item Client-side state management with Redux Toolkit and local offline storage using SQLite via Drizzle ORM.
\end{itemize}

The backend and integration scope included:
\begin{itemize}
    \item Backend modules in NestJS 11 with MongoDB 8 for User Management, Workout Management (CRUD and batch sync), and Feature Management (dynamic flags).
    \item An authenticated network client implementing JWT token injection and single-flight 401 refresh interceptors.
    \item Quality assurance through unit tests, static type verification, and linting.
\end{itemize}

\subsection{Limitations}
\begin{itemize}
    \item The internship was limited to the 12-week timeframe prescribed by the university curriculum, requiring prioritization of core features over secondary enterprise features.
    \item Development was undertaken by the intern as a single contributor, requiring sequential execution of frontend and backend milestones.
    \item Application testing was performed exclusively on emulators and automated test environments; physical device testing was not conducted.
    \item Third-party production credentials (Google OAuth, Apple Developer) and cloud deployment pipelines were not configured; integration was validated against local development instances.
    \item The legacy backend (ASP.NET Core) was a pre-existing dependency and was not modified during the internship.
\end{itemize}
