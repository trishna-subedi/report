\section{Roles and Responsibilities}
During the twelve-week internship at Power Gym Budibazar Pokhara, the intern was assigned the role of Mobile Application Developer Intern within the Digitalization Unit.

The primary role was frontend development and UI implementation, involving application screens and interface components such as layouts, buttons, cards, input fields, text, spacing, and navigation between screens. The focus was on implementing the user interface according to the required design and ensuring a consistent and functional user experience.

In addition to frontend development, the intern contributed to basic backend development and frontend--backend integration. Backend responsibilities included working with User Management, Workout Management, and Feature Management functionalities---specifically retrieving and updating user information, creating, retrieving, updating, and deleting workout data, and connecting these services with the frontend.

The intern also worked with feature flags that allowed application features to be enabled or disabled through backend configuration. Further responsibilities included connecting frontend components with backend services, handling the required data flow, testing implemented screens and functionalities, and fixing errors and bugs identified during development.

Through these responsibilities, the intern applied concepts learned during the B.Sc. CSIT program to a real mobile application, gaining practical experience in frontend development, backend integration, testing, debugging, and the overall software development process.

\section{Description of the Project(s) Involved During Internship}
The project developed during the internship is \textbf{Alcedo}, a cross-platform mobile fitness application for Power Gym Budibazar Pokhara.

\subsection{Product Purpose}
Alcedo provides gym members with an offline-capable mobile companion to replace paper logs with structured digital tracking. Members can log workouts, track exercises and sets, consult exercise catalogs, view performance trends, and manage preferences. The core interface screens are shown in Figure~\ref{fig:app-screens}.

\subsection{System Architecture}
The Alcedo platform comprises multiple components:
\begin{enumerate}
    \item \textbf{Mobile Client (app/):} Cross-platform application built with React Native 0.86, Expo SDK 57, and TypeScript. Provides the user interface, local SQLite persistence via Drizzle ORM, Redux Toolkit state management, and secure token storage.
    \item \textbf{Modern Backend (backend-v2/):} RESTful server built on NestJS 11 and MongoDB 8, handling user management, workout synchronization, feature flags, and site configuration.
    \item \textbf{Legacy Service (backend/):} Pre-existing ASP.NET Core backend maintained as an external dependency.
    \item \textbf{Web Portal (website/):} Supplementary Next.js web interface for account management.
\end{enumerate}

\section{Tasks/Activities Performed}
This section describes the technical activities executed during the internship, organized by domain.

\subsection{Development Environment Setup}
The initial phase involved configuring the development environment. Key configurations included strict TypeScript compiler settings, Metro bundler with SVG transformer plugins, path aliases for module resolution, and Oxlint/ESLint for code style enforcement.

\subsection{Reusable Components and Design System}
To maintain visual consistency across screens, a foundation component library comprising 82 modular components was built. The design system is anchored by centralized design tokens defining color palettes (Light, Dark, and OLED modes), typography scales, and spacing metrics. Standardized components include buttons (primary, tonal, outlined variants), cards, input fields, dialogs, and tab bar icons.

\subsection{Navigation and Screen Implementation}
Application navigation was implemented using Expo Router with 49 route files organized into a tab-based hierarchy. The bottom tab navigator provides five tabs:
\begin{enumerate}
    \item \textbf{Workout:} Session initiation, live set logging, rest timers, and post-workout summaries.
    \item \textbf{Feed:} Social timeline, shared workouts, and profile editing.
    \item \textbf{Stats:} Volume heatmaps, personal record tracking, and strength curves.
    \item \textbf{History:} Monthly calendar, session review, and historical editing.
    \item \textbf{Settings:} Profile management, theme selection, backup tools, and backend diagnostics.
\end{enumerate}

\subsection{State Management with Redux Toolkit}
Client-side state was structured using Redux Toolkit across 11 domain slices covering session tracking, workout history, exercise definitions, user preferences, backend configuration, and authentication state. A listener middleware intercepts specific actions to trigger non-blocking side-effects such as SQLite persistence and cache invalidation.

\subsection{Local Data Storage with SQLite and Drizzle ORM}
Offline-first persistence was implemented using an embedded SQLite database managed through Drizzle ORM. The schema comprises 17 relational tables covering workout sessions, exercise records, set logs, blueprint plans, exercise definitions, and synchronization metadata. Schema evolution is handled through nine sequential SQL migrations executed transactionally at application startup. JWT tokens are stored separately using Expo SecureStore for hardware-backed cryptographic isolation.

\subsection{Frontend--Backend Integration}
Client--server communication is mediated by a centralized wrapper that automatically injects JWT access tokens into outgoing requests. When a 401 response is received, the wrapper pauses concurrent requests, executes a single token refresh, updates credentials, and replays queued requests. The mobile client also queries a feature endpoint to discover available backend capabilities and adapt the UI accordingly.

\subsection{User Management Module}
The User Management module in the NestJS backend provides profile retrieval and update endpoints. Profile data is fetched via a GET endpoint and updated via a PATCH endpoint, with request validation enforced through DTOs.

\subsection{Workout Management and Synchronization}
The Workout Management module implements CRUD operations for workout sessions and set records. Each document uses version integers for compare-and-set conflict prevention. Soft deletes generate tombstone records for synchronization. Batch push/pull endpoints with idempotency keys were developed and validated for future multi-device replication.

\subsection{Feature Management}
Feature Management operates through a public endpoint distributing boolean feature flags (feed, backup, AI planner, sharing) consumed by the mobile client's capability probe. An administrative site configuration service manages system keys with AES-256-GCM encryption for sensitive values.
